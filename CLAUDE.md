# Проект: сайт Harmony Dental Clinic

Домен: https://harmonyclinic.od.ua
Статический сайт (HTML/CSS/JS), сервер nginx + Apache (`.htaccess` работает).
Двуязычный: украинская версия в корне, русская в `/ru/`.

## Структура каталогов

```
Сайт/
├── Harmony Dental Clinic/   ← ПРОДАКШЕН. Только это заливается на хостинг
├── _work/                   ← РАБОЧАЯ ПАПКА. На хостинг НЕ заливается
│   ├── audits/              аудиты (SEO, скорость, доступность, безопасность)
│   ├── reports/             отчёты, аналитика, выгрузки, замеры позиций
│   ├── scripts/             служебные скрипты (обработка картинок, парсинг, миграции)
│   ├── backups/             резервные копии файлов перед правками
│   └── notes/               заметки, планы, черновики, семантика, ТЗ
└── CLAUDE.md                этот файл
```

## Главное правило: где что сохранять

**Всё, что не должно попасть на хостинг, сохраняется в `_work/`, а не в папку сайта.**

В `_work/` идут: аудиты, отчёты, планы, чек-листы, семантические ядра, служебные
и одноразовые скрипты, бэкапы, логи, эксперименты, промежуточные результаты, любые
`*.md`-документы для администрирования.

В `Harmony Dental Clinic/` кладутся **только** файлы, которые должны быть публично
доступны по URL: `.html`, `.css`, `.js`, изображения, `robots.txt`, `sitemap.xml`,
`.htaccess`, `site.webmanifest`, файлы верификации поисковиков.

Если сомневаешься, попадёт ли файл на прод — значит, он идёт в `_work/`.

Никогда не создавать в `Harmony Dental Clinic/` файлы вида `README.md`, `NOTES.md`,
`TODO.md`, `*.backup`, `*.old`, `*.py`, `*.sh`, тестовые страницы, копии страниц
для сравнения. Всё это — в `_work/`.

### Перед правкой боевых файлов

Копию исходного файла класть в `_work/backups/` с датой в имени:
`_work/backups/2026-08-06_index.html`

## Именование файлов в `_work/`

- Аудиты и отчёты: `ТИП-ГГГГ-ММ.md` — например `SEO-AUDIT-2026-08.md`
- Бэкапы: `ГГГГ-ММ-ДД_имя-файла.расширение`
- Скрипты: осмысленное имя на латинице, `convert-to-webp.py`

## Гигиена продакшен-папки

На хостинге не должно быть служебного мусора. Регулярно проверять и удалять:
`.DS_Store`, `.fuse_hidden*`, `*.backup`, `*.old`, неиспользуемые изображения.
На момент августа 2026 в `/blog/` лежали 11 файлов `.fuse_hidden*`, доступных
публично с кодом 200 — такие вещи находить и удалять.

## Режим работы

Автономный режим (см. также общее правило в [../CLAUDE.md](../CLAUDE.md) и
[../Мое хранилище/_Claude_Instructions/rules.md](../Мое%20хранилище/_Claude_Instructions/rules.md)):
в рамках этого проекта — зелёный свет. Вносить правки, создавать и удалять
файлы, выполнять задачу от начала до конца без уточняющих вопросов и без
запроса ОК на план. Сначала делать, потом отчитываться.

Спрашивать разрешение только в двух случаях:
1. Радикальное/глобальное изменение с риском для большого объёма данных —
   заливка на хостинг, массовое удаление файлов на сервере, реструктуризация
   всего сайта.
2. Выход в интернет / браузер — публикация, изменения в Google Business
   Profile, отправка данных третьим лицам, любые действия на внешних сайтах
   и сервисах.

## Правила верстки и работы с изображениями (CSS / WebP / Picture)

1. **Глобальный ресет для `<picture>` и `<img>`:**
   В `styles.css` и во всех внутренних `<style>` блоках **обязательно** должно присутствовать:
   ```css
   picture { display: contents; }
   img, svg, video { max-width: 100%; height: auto; }
   ```
   - `picture { display: contents; }` критически важен: тег `<picture>` по умолчанию строчный (`display: inline`). Без `display: contents` он ломает сетки (Grid/Flexbox) и процентные размеры `width: 100%` на `<img>`.
   - `img { max-width: 100%; height: auto; }` должен быть объявлен **на глобальном уровне (для всех экранов)**, а не только внутри мобильных `@media (max-width: 992px)`.

2. **Фиксированные логотипы и иконки:**
   Для логотипов и иконок с фиксированной высотой (`height: 50px`, `max-height: 60px`) **всегда указывать `width: auto`**:
   ```css
   .logo img, header .logo img { width: auto; height: auto; max-height: 60px; filter: brightness(0) invert(1); }
   .unified-footer .footer-logo-img { width: auto; height: 50px; filter: brightness(0) invert(1); margin-bottom: 15px; }
   ```
   Иначе браузер при наличии HTML-атрибутов `width="1072" height="1071"` растянет картинку на 1072px в ширину.

3. **HTML-атрибуты `width` и `height`:**
   Указывать натуральные размеры для предотвращения CLS (Cumulative Layout Shift), но всегда в паре с `max-width: 100%; height: auto;` в CSS.

4. **Пути к фоновым изображениям:**
   Проверять реальное существование файлов для `background: url(...)`. Для страниц в папке `/ru/` использовать относительные пути `../images/...`.
