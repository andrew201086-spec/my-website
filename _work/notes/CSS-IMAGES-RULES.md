# Инструкция и правила: работа с изображениями, тегом <picture> и размерами в CSS

Дата составления: 16.08.2026

## 1. Проблема, которая произошла

При массовом добавлении тегов `<picture><source srcset="...webp"><img ...></picture>` и атрибутов `width="..." height="..."` все изображения на сайте исказились, растянулись или вылезли за пределы контейнеров.

### Причины:
1. **Тег `<picture>` является строчным (`display: inline`)**:
   - Когда `<img>` оборачивается в `<picture>`, родительские контейнеры (`.team-card`, `.feature-item`, `.photo-wrapper`, `.about-img`) перестают напрямую управлять стилями `<img>`.
   - В правилах вида `.photo-wrapper img { width: 100%; }` ширина `100%` считается от строчного контейнера `<picture>` с `width: auto`, из-за чего браузер подставляет физический размер из HTML-атрибута `width="1820"` (картинка раздувается до 1820px).
2. **Адаптивность `img { max-width: 100%; }` была спрятана в `@media (max-width: 992px)`**:
   - На десктопах (> 992px) картинки не имели ограничения `max-width: 100%` и рендерились в полный размер своих HTML-атрибутов.
3. **Логотипы растягивались по горизонтали**:
   - У логотипа стояли атрибуты `width="1072" height="1071"`, а в CSS — `height: 50px` или `max-height: 60px` без `width: auto`. Браузер вычислял ширину 1072px при высоте 50px, превращая логотип в сплюснутую полосу.

## 2. Обязательные стандарты верстки

### Правило 1: Базовый ресет
В файле `styles.css` и в любых `<style>` блоках на страницах **всегда** должен быть ресет:

```css
picture {
    display: contents;
}
img, svg, video {
    max-width: 100%;
    height: auto;
}
```

> **Почему `display: contents`?**  
> Свойство `display: contents` убирает визуальную «коробку» тега `<picture>` из дерева рендеринга. Для CSS-сеток (Grid, Flexbox), позиционирования и процентной ширины тег `<img>` начинает вести себя так, будто он вложен напрямую в родительский блок.

---

### Правило 2: Логотипы и фиксированные по высоте элементы
Для любых изображений, где в CSS задается фиксированная высота (`height` или `max-height`), обязательно указывать `width: auto`:

```css
.logo img, header .logo img {
    width: auto;
    height: auto;
    max-height: 60px;
    filter: brightness(0) invert(1);
}

.unified-footer .footer-logo-img {
    width: auto;
    height: 50px;
    filter: brightness(0) invert(1);
    margin-bottom: 15px;
}
```

---

### Правило 3: SEO-атрибуты width и height
Для предотвращения CLS (Cumulative Layout Shift) все теги `<img>` должны иметь атрибуты `width` и `height` с реальными размерами файла:

```html
<picture>
    <source srcset="images/andrey.webp" type="image/webp">
    <img src="images/andrey.jpg" class="team-photo" alt="Лікар Малюкін Андрій Віталійович" loading="lazy" width="725" height="1024">
</picture>
```

---

### Правило 4: Проверка фоновых изображений (CSS background)
При использовании `background-image: url(...)`:
- Убедиться, что файл физически существует на диске (не ссылаться на несуществующие файлы вроде `clinic-bg.jpg`).
- Для страниц в подпапке `/ru/` путь к папке картинок должен быть `../images/...`, а не `images/...`.
