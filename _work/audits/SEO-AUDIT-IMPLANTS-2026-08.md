## 1. КРИТИЧНО: Каннибализация со статьёй блога

`/blog/implantatsiya-zubiv-povnyi-gayd.html` — 1922 слова, «Одеса» упоминается **34 раза**, есть разметка FAQPage. Это не информационная статья, а второй лендинг по имплантации.

Совпадение разделов со сервисной страницей — 8 из 13:

| Раздел статьи | Раздел сервисной страницы |
|---|---|
| Кому показана імплантація | Показання та протипоказання |
| Види імплантації — який метод обрати | Види імплантації зубів |
| Як проходить імплантація: етапи | Календар лікування |

| Від чого залежить вартість | Пояснение к ценам |
| Чи боляче і як проходить відновлення | Догляд і реабілітація |

| Скільки служить і які гарантії | FAQ |
| FAQ (FAQPage) | FAQ (FAQPage) |

**Часть проблемы создана правками от 12.08.** Разделы «Види імплантації», «Імплант vs міст», «Календар лікування», «Показання та протипоказання» добавлялись на сервисную страницу без сверки с блогом. До правок пересечение было минимальным — страница была слишком тонкой (479 слов), чтобы с чем-то конкурировать.

**Почему это вредит:** Google выберет одну страницу из двух под «імплантація зубів Одеса» и может выбрать статью — она старше и уже проиндексирована. Статья хуже конвертирует: нет цены 620 $, нет кнопки записи, нет прайса. Плюс две страницы с FAQPage по одной теме на одном домене — сигнал дублирования.

**Что делать (в таком порядке):**

1. **Сначала посмотреть Search Console** — по запросу «імплантація зубів Одеса» и близким: какой URL получает показы. Это решает, кого двигать. Действовать вслепую нельзя.
2. **Расчистить статью под информационный интент:** убрать «в Одесі» из title, H1 и description; сократить упоминания города с 34 до 3–5; убрать разметку FAQPage — оставить её только на сервисной странице.
3. **Убрать из статьи разделы-дубли**, заменив их 2–3 предложениями со ссылкой на сервисную страницу.
4. **Canonical со статьи на услугу НЕ ставить.** Интенты разные — потеряете информационный трафик целиком.

## 2. ВЫСОКИЙ: WebP лежит на сервере, но не используется — 403 КБ впустую

Для всех восьми кейсовых фото и для фото хирурга есть готовые `.webp`. Страница грузит `.jpg`.

| | Сейчас (JPG) | Есть (WebP) | Экономия |
|---|---|---|---|
| 8 кейсов «до/после» | 685 КБ | 350 КБ | 335 КБ (49 %) |
| `oleg.jpg` (фото хирурга) | 96 КБ | 29 КБ | 68 КБ (70 %) |
| **Итого** | **782 КБ** | **379 КБ** | **403 КБ** |

**Паттерн на сайте уже применяется**: логотип в шапке отдаётся через `<picture><source srcset="images/Logo.webp" type="image/webp">`. MIME-тип для webp в `.htaccess` прописан. Всё готово — просто на этой странице не сделано.

```html
<picture>
  <source srcset="images_implants/c1b.webp" type="image/webp">
  <img src="images_implants/c1b.jpg" width="800" height="600" loading="lazy" alt="...">
</picture>
```

## 3. ВЫСОКИЙ: 12 из 13 изображений без width/height — CLS

Ни у одной картинки в карусели кейсов нет атрибутов размера. Контент прыгает при загрузке — прямой удар по Cumulative Layout Shift. CSS `aspect-ratio` в `.photo-wrapper` есть, но браузеру нужны атрибуты в HTML, чтобы зарезервировать место до загрузки CSS.

## 4. ВЫСОКИЙ: Hero-изображение не оптимизировано под LCP

`images/oleg.jpg` в первом экране — почти наверняка LCP-элемент. Сейчас: 96 КБ JPG, без WebP, без размеров, без приоритета. Нужно: `<picture>` с WebP (29 КБ), `width`/`height`, `fetchpriority="high"`, **без** `loading="lazy"`.

## 6. СРЕДНИЙ

**6.1 В sitemap.xml у страницы нет hreflang-альтернатив.** У главной, страницы врача и отбеливания блоки `xhtml:link` есть, у `implants-ua.html` и `/ru/implants-ua.html` — нет. После заливки обновить `lastmod` (сейчас `2026-08-06`).

**6.2 URL не совпадает с семантическим ядром.** В документе целевой URL — `/implantatsiya-zubiv`, фактический — `/implants-ua.html`. Суффикс «-ua» на русской версии (`/ru/implants-ua.html`) выглядит странно. Редирект `^implantatsiya/?$` в `.htaccess` уже стоит. **Менять URL — риск**: только с аккуратными 301 и готовностью к просадке на 2–4 недели. Если страница уже собирает трафик — не трогать.

**6.3 Слово «ціна» в видимом тексте 1 раз** на 2867 слов — везде «Вартість». Добавить в H2: «Ціни на імплантацію зубів в Одесі — вартість під ключ».

**6.4 «Одеса» — 8 раз на 2867 слов.** Для гео-коммерческой страницы мало, ориентир 12–15. Добавлять в заголовки блоков и подписи к кейсам.

**6.5 Не покрыты два кластера из ядра:** «вставити зуб» и «корейські імпланти». Второе решается одной правкой: написать `Osstem (Корея)` — марка корейская, запрос закроется без вранья.

**6.6 11 из 13 изображений без `loading="lazy"`** — вся карусель кейсов грузится сразу.

## 7. НИЗКИЙ: гигиена и доступность

- **Нет `<main>`** — ни одного `<main>` или `<article>`, landmark-структуры нет.
- **17 аккордеонов на `<div onclick>`** — без `role="button"`, `tabindex="0"`, `aria-expanded`. С клавиатуры FAQ не открыть, скринридер не поймёт состояние.
- **Инлайн `<style>` 20 КБ + инлайн `<script>` 19 КБ** в каждом HTML — 39 КБ дублируются на всех страницах и не кешируются между переходами.
- **Google Fonts подключён render-blocking** `<link rel="stylesheet">`; `preconnect` есть, но шрифт всё равно блокирует рендер.
- **Одна `<img>` с пустым alt** — если декоративная, всё в порядке.

## 8. Что сделано хорошо (не ломать)

`.htaccess` — сильная сторона проекта:

- HTTPS форсируется, `www` → без `www`, `/index.html` → `/` (301, без циклов)
- gzip **и** brotli для html, css, js, json, ld+json, xml, svg
- Кеш: HTML — 0 сек, CSS/JS — месяц, картинки и шрифты — год
- Security headers: HSTS с preload, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, настроенный CSP
- MIME-типы для `.webp` и `.avif` прописаны
- Закрыты `.py`, `.backup`, `.md`, `.sh`, `.log`, `.DS_Store`, `.fuse_hidden*` — дыра из прошлого аудита закрыта
- 301 со старых WordPress-URL настроены

Остальное:

- `robots.txt` корректен, sitemap объявлен
- canonical и hreflang (uk-UA / ru-UA / x-default) на самих страницах верные
- Аналитика (GTM, gtag, FB Pixel) грузится по первому взаимодействию, а не в рендер — грамотно для Core Web Vitals
- alt у всех содержательных изображений заполнены осмысленно, с гео

## 10. Чего в этом аудите нет

Не было доступа к Google Search Console, Google Analytics и к живому сайту. **Не проверены:**

- реальные позиции и то, какая из двух страниц ранжируется
- фактические Core Web Vitals по полевым данным (CrUX)
- реальные коды ответа сервера и работа редиректов
- ссылочный профиль и конкуренты в выдаче Одессы
- поведение: глубина скролла, доходят ли до блока цен

Без этих данных пункты про каннибализацию и смену URL — обоснованные гипотезы, требующие проверки по GSC перед действием.
