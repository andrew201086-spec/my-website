## Резюме

Техническая база сайта — выше среднего по рынку (структурированные данные, hreflang, редиректы, безопасность, кэш настроены грамотно). ## 2. Скорость и Core Web Vitals — критично

### 2.1 Вес изображений

| Страница | Вес картинок |
|---|---|
| services-ua.html | **2.95 MB** |
| maliukin-andriy.html | 1.84 MB |
| orthodontics-ua.html | 1.83 MB |
| index.html | 1.76 MB |
| lechenie-ua.html | 1.72 MB |
| hygiene-ua.html | 1.39 MB |

Отдельные файлы: `ot_fayla_k_koronke.jpg` — 1.03 MB, `cadcam-dental-workflow.png` — 701 KB, `doctor-portrait.png` — 662 KB, `clinic.jpg` — 627 KB. Всего в проекте 31 PNG, многие — фотографии, сохранённые в PNG вместо WebP.

**73 файла PNG/JPG уже имеют готовый WebP-дубликат**, но HTML продолжает ссылаться на тяжёлую версию. Потенциальная экономия только на этом — **5.2 MB** без единой новой конвертации.

`<picture>` с WebP применён выборочно: на index (23 из 26), prosthetics (18 из 22), но на implants — 1 из 12, на hygiene — 1 из 10, на orthodontics — 1 из 13, на lechenie — 1 из 12.

### 2.2 CLS — сдвиг макета

**272 из 330 `<img>` по всему сайту не имеют атрибутов `width` и `height`.** Это прямая причина Cumulative Layout Shift, одного из трёх Core Web Vitals. На главной — 24 из 26 картинок без размеров.

### 2.3 Lazy loading

104 из 330 картинок без `loading="lazy"`. На implants-ua — 11 из 12, на hygiene — 9 из 10, на orthodontics — 8 из 13.

### 2.4 Оптимизация применена только к главной

На `index.html` аналитика (GTM, gtag, Facebook Pixel) грамотно отложена до первого взаимодействия — отличное решение. На **всех остальных страницах** GTM и gtag.js грузятся в самом верху `<head>` синхронно, плюс подключается render-blocking `styles.css` и Google Fonts. То есть внутренние страницы — а это и есть посадочные страницы под коммерческие запросы — не получили ни одной из оптимизаций главной.

### 2.5 `<meta charset>` вне первых 1024 байт

| Страница | Позиция charset |
|---|---|
| index.html | байт **2759** |
| ru/index.html | байт **2759** |
| implants-ua.html | байт **1735** |
| services-ua.html | байт 747 ✓ |

Спецификация HTML требует объявления кодировки в первых 1024 байтах. Сервер отдаёт `Content-Type: text/html` **без `charset=utf-8`**, поэтому браузер обязан угадывать кодировку и при обнаружении meta-тега перезапускает парсинг документа. Это и задержка рендера, и потенциальные «кракозябры».

### 2.6 Битая ссылка на изображение

`implants-ua.html` ссылается на `images/clinic-bg.jpg` — файла не существует.

### 2.7 Мусор на сервере

В `/blog/` лежат 11 файлов `.fuse_hidden*` — остатки прерванной загрузки по FTP/FUSE. Проверено: **они отдаются публично с кодом 200** (например `.fuse_hidden0000001200000003` — 97 KB, старая копия статьи об имплантации). Плюс 39 неиспользуемых изображений на 5.8 MB и `.DS_Store` в корне.

## 3. Техническая часть — что уже хорошо

Чтобы не переделывать то, что работает:

- `robots.txt` корректен, sitemap указан, sitemap отдаётся (200, 7.2 KB)
- hreflang uk-UA / ru-UA / x-default — **реализован без единой ошибки**, взаимные ссылки согласованы, canonical на каждой странице
- HTTP → HTTPS и www → без-www: 301, работают
- Gzip работает (120 KB → 23.8 KB), HTTP/2, HSTS, CSP, X-Frame-Options
- Кэширование: HTML 0 сек, картинки 1 год, CSS/JS 1 месяц — разумно
- Структурированные данные: Dentist + MedicalClinic, Physician, WebSite, BreadcrumbList, FAQPage, Service, Offer, HowTo, Article — **весь JSON-LD валиден**, ошибок парсинга нет
- NAP полный: адрес (вул. Новаторів, 1А, 65114), координаты, часы работы, телефон
- `areaServed` с районами: Таїрова, Черемушки, Сьомий кілометр, Київський район
- Карта Google — `loading="lazy"`
- Все 330 картинок имеют `alt`
- Битых внутренних ссылок нет
- Уникальные title и description на каждой странице, длины в пределах нормы

### Мелкие технические замечания

- `/index.html` отдаёт 200 (дубль главной). Canonical проблему закрывает, но лучше 301 на `/`
- `AggregateRating` (5.0, 47 отзывов) размечен на самой `Dentist` — Google считает отзывы, собранные бизнесом на собственном сайте, «self-serving» и не показывает по ним звёзды. Разметка не даст эффекта, а риск ручных санкций ненулевой
- `<meta name="keywords">` — не используется поисковиками с 2009 года, можно удалить
- `404.html` и `ru/404.html` — без description и canonical
- `lastmod` во всём sitemap стоит статичный 2026-06-21 — теряется сигнал свежести
- Slug'и не содержат ключей: `implants-ua.html` вместо `implantatsiya-zubiv`, `lechenie-ua.html` вместо `likuvannya-zubiv`. Русские страницы лежат по адресам с суффиксом `-ua` (`/ru/lechenie-ua.html`) — выглядит как ошибка. **Менять URL сейчас рискованно** — только вместе с 301 и только если решитесь на редизайн структуры
- Нет Brotli (только gzip) — минус ~15% к весу текстовых файлов

## 4. Off-page — то, что решает топ-5 по гео

По запросам вида «стоматология Одесса» верхнюю часть выдачи занимает **локальный пак (карта + 3 клиники)**, и только под ним — органика. Попасть в топ-5 без работы с Google Business Profile невозможно.

Что нужно проверить и делать (аудит по коду это не покажет):

1. **Google Business Profile** — заполнен ли на 100%: категории (основная «Стоматологическая клиника» + дополнительные), услуги с ценами, фото (минимум 30, обновлять ежемесячно), часы работы, атрибуты, ссылки на конкретные страницы услуг, а не только на главную
2. **Отзывы в GBP** — главный фактор локального ранжирования. У лидеров Одессы 150–400 отзывов. На сайте заявлено 47. Нужен процесс: QR-код в клинике, сообщение пациенту после приёма, ответ клиники на каждый отзыв
3. **Google Posts** — 1–2 публикации в неделю в профиле
4. **Локальные каталоги**: dok.ua, likarni.com, ua.kompass, doc.ua, 2gis, Ukr.net-каталоги, otzyvua.net — с идентичным NAP (символ в символ, включая «вул. Новаторів, 1А»)
5. **Ссылки**: медицинские порталы, местные СМИ (Odessa.online, Думская), гостевые экспертные статьи от Малюкіна Андрія, партнёрства
6. **YouTube/Instagram/TikTok** — каналы уже есть в разметке, нужны ссылки на страницы услуг из описаний

## 5. План действий

### Спринт 1 (1–2 недели) — техника, максимум эффекта за минимум работы

1. Перенести `<meta charset="UTF-8">` в самое начало `<head>`, до всех скриптов, на всех страницах. Добавить `charset=utf-8` в Content-Type на сервере
2. Проставить `width` и `height` всем 272 картинкам (CLS)
3. Проставить `loading="lazy"` 104 картинкам ниже первого экрана
4. Перевести ссылки на 73 картинки с готовым WebP-дубликатом на `<picture>` — минус 5.2 MB
5. Пережать в WebP оставшиеся PNG (`ot_fayla_k_koronke.jpg` 1 MB, `cadcam-dental-workflow.png` 701 KB, `doctor-portrait.png` 662 KB и др.)
6. Перенести схему отложенной загрузки аналитики с index.html на все внутренние страницы
7. Удалить с сервера `.fuse_hidden*`, `.DS_Store`, 39 неиспользуемых изображений (5.8 MB)
8. Починить `images/clinic-bg.jpg`
9. 301 с `/index.html` на `/`, с `/ru/index.html` на `/ru/`
10. Убрать `aggregateRating`/`review` с узла `Dentist` либо заменить на ссылку на отзывы в GBP

**Ожидаемый эффект:** PageSpeed mobile +25–40 пунктов, CLS в зелёную зону, LCP −1–2 с.

### Спринт 2 (3–6 недель) — контент денежных страниц

15. Страницы остальных четырёх врачей + перелинковка со страниц услуг («хирург Олег Швец» → ссылка на его страницу)
16. Поднять перелинковку на страницу главврача: ссылка из каждой услуги, из каждой статьи блога, из футера

### Спринт 3 (2–3 месяца) — расширение семантики
